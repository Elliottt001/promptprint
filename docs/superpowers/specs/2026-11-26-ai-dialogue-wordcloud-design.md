# AI 对话词云网页设计

日期：2026-11-26

## 目标

从支持的公开 AI 产品本地对话数据中，仅提取用户本人发出的消息，生成一个设计美观、可交互、可离线打开的词云网页。页面提供两套可即时切换的统计口径：

- **主题提纯**：忽略停用词、泛词、路径噪声与代码符号，突出项目、课程、产品和技术主题。
- **原始词频**：保留“实现、需要、文件”等泛词，只过滤纯标点、无意义碎片与自动注入内容。

ChatGPT 数据不在本次范围内。

## 数据边界与隐私

数据源只读，扫描范围限定为已知公开产品的数据目录和数据库。提取器只接受明确标记为用户角色的正文，排除：

- AI、系统、开发者及工具消息；
- 工具调用、命令输出、日志和模型推理；
- 自动注入的 `environment_context` 等运行环境信息；
- 空消息、损坏记录及完全重复的跨产品记录。

所有解析与统计均在本机执行。最终网页只包含词语、频次、产品分布和按月聚合的趋势，不嵌入完整对话原文，也不向网络上传数据。

## 方案选择

采用“本地预处理 + 静态单页网页”。一个 Python 脚本只读扫描各来源，完成解析、去重、分词与聚合，输出网页所需的精简 JSON；静态页面读取聚合数据并渲染交互。

不采用动态服务，因为每次打开都重扫数 GB 数据会降低体验；不采用浏览器直接读取原始数据，因为浏览器权限、SQLite 和多种 JSONL 格式会显著增加实现与使用成本。

## 组件与数据流

### 1. 数据提取器

每个来源使用独立的小型解析函数，统一输出以下内部记录：

```text
{ source, conversation_id, timestamp, text }
```

解析失败时跳过单条记录并计入诊断汇总，不中断全量生成。源文件始终以只读方式打开。

### 2. 清洗与去重

正文先移除自动上下文包装、URL 查询参数、长哈希、绝对路径和结构化日志噪声，但保留自然语言中的产品名、课程名和技术词。去重键由规范化正文生成；同一内容跨产品出现时只计一次，同时保留它出现过的来源集合。

### 3. 分词与两套词频

优先复用本机已有的中文分词能力；若没有合适依赖，则使用轻量规则分词与中英文 token 提取，避免为了单次静态产物引入大型服务。

基础 token 流同时进入两条管线：

- 原始词频管线只做最低限度的有效性过滤；
- 主题提纯管线额外应用中文停用词、会话泛词、路径与代码噪声过滤。

两条管线分别聚合总频次、各产品频次和月度频次。输出限制为足够支持交互的 Top 词集合，避免把低频隐私片段带入网页。

### 4. 静态数据

本机聚合输出到 Git 忽略的 `web/data.local.json`；仓库只保留空快照。聚合文件包含：

- 生成时间、覆盖时间范围；
- 扫描会话数、用户消息数、有效文本量；
- 各产品的记录计数；
- 两套词频及每个词的来源、趋势数据；
- 被跳过或无法解析的记录数量，不包含原始内容。

### 5. 交互页面

页面采用深色“语言星云”视觉：克制的蓝紫渐变、柔和光晕、低密度粒子背景和高对比文字。核心区域为响应式词云，兼顾桌面与窄屏。

主要交互：

- “主题提纯 / 原始词频”分段切换，词语平滑重排；
- 公开产品多选筛选（TRAE CN 加密数据库当前不支持读取）；
- Top 数量调节与关键词搜索；
- 悬停显示词频，点击打开详情面板；
- 详情展示产品占比和月度使用趋势；
- 数据概览展示覆盖范围、消息量与来源构成；
- 导出当前词云为 PNG；
- 尊重 `prefers-reduced-motion`，键盘可操作并提供可读焦点状态。

页面不依赖后端。默认通过一个轻量本地静态服务器打开，以避免浏览器对 `file://` 加载 JSON 的限制。

## 错误处理

- 数据目录不存在：标记该来源为不可用，继续处理其他来源。
- 单文件或单条记录损坏：跳过并累计诊断数。
- 最终没有有效词语：生成带有明确空状态的页面，而不是失败或显示示例数据。
- 字体或动画能力不足：回退到系统中文字体和无动画布局。
- PNG 导出失败：页面继续可用，并显示简短错误提示。

## 验证

实现后至少完成以下检查：

1. 用最小合成样本验证四类解析器只提取用户消息。
2. 验证自动环境上下文、系统消息、AI 回复和工具输出不会进入词频。
3. 验证重复正文只计一次，而来源集合正确合并。
4. 验证两套口径对泛词产生预期差异。
5. 对真实数据运行全量生成，核对来源计数、跳过计数和非空 Top 词。
6. 在本地浏览器检查切换、筛选、搜索、详情、响应式布局和 PNG 导出。

## 产物

项目保持最小化，预计包含：

- 一个本地数据生成脚本；
- 一个小型解析/清洗测试；
- 一个静态页面及其样式和交互脚本；
- 一个聚合后的数据文件；
- 简短 README，说明生成、打开和刷新数据的方法。

不建立后端、账号系统、数据库或构建流水线；除非现有环境确有必要，也不引入前端框架。
